# Documentation

## Core rules

- Update docs with the behavior in the same change (README, usage, config, env var names, changelog where kept).
- Document only what exists; keep it concise and link to the source of truth. Comments explain why, not what.

## Details

- New commands, scripts and configuration options get one example each.
- Known limitations and unverified behavior are stated plainly.
- Future, optional work goes in the project's roadmap, not in user docs.
